# Short-string mistranslations (DeepL, no context)

**Filed:** 2026-06-17
**Found while:** polishing the admin UI of the `heads-up-mailer`
plugin, whose `languages/` are generated by this tool.
**Status:** notes for a future wp-translate-tool improvement. The
affected plugin files were hand-corrected in place; those fixes will
be **overwritten on the next regen** unless this is addressed here.

## Summary

Short, context-free UI strings are systematically mistranslated by
DeepL — **the same errors appear in every locale** (de, es, fr, it,
nl, pl, el, and even en-GB). Long, sentence-like strings translate
fine. The failures cluster into three classes:

1. **Wrong sense of a polysemous word.** DeepL guesses the wrong
   meaning when there's no surrounding context.
   - `Sent` (email status) → translated as *late / delayed*
     (de "Spät", es "Tarde", fr "Tard/En retard", it "Tardi/In
     ritardo", nl "Laat", pl "Późno/Opóźnienie", el "Αργά"). DeepL
     read "Sent" as a typo/variant of a tardiness word rather than
     the past participle of *to send*.
   - `Folder` (IMAP mailbox folder) → *brochure / leaflet*
     (de "Broschüre", es "Folleto", fr "Dépliant", it "Opuscolo",
     nl "Brochure", pl "Ulotka", el "Φυλλάδιο").

2. **Acronym expansion.** Technical acronyms get "helpfully"
   expanded into prose.
   - `TLS` → "The latest security standards" (and its translations:
     de "Die neuesten Sicherheitsstandards", etc.).
   - `ID` → "Identification number" (de "Identifikationsnummer",
     fr "Numéro d'identification", etc.).

3. **Harmless reordering** (not a bug, noted for completeness).
   - `Footer HTML` → "HTML footer" / "HTML-Fußzeile". Meaning
     preserved; left as-is.

Knock-on effect: compound strings built on a mistranslated root
inherit the error — `Sent log`, `Sent (%d)`, `Sent / Total`,
`Sent at (UTC)` were all wrong wherever the root `Sent` was wrong.

Interesting: `Sent at (UTC)` translated **correctly** in most
locales — the trailing words gave DeepL enough context to pick the
*dispatch* sense. The bare `Sent` had none, so it failed. This is
the core lesson: **context is the variable, not the language.**

## Why this happens (tool-side)

From `src/deepl.ts`: standard entries are batched 50/request with no
context; only entries carrying a `msgctxt` are sent individually so
DeepL can use the context. Short UI labels rarely have a `msgctxt`,
so they go through the contextless batch path — exactly where DeepL
is weakest. Acronyms and polysemous single words are the worst case.

## Possible remedies (for a future wp-translate session)

Rough order of effort vs. payoff:

- **A. Glossary file (recommended).** A per-locale overrides map
  (`glossary.<locale>.json` or one TSV) applied *after* DeepL,
  before the `.po` is written. Cheapest durable fix; the table above
  is the seed data. Keep acronyms (`TLS`, `ID`, `API`, `SMTP`,
  `IMAP`, `URL`, `HTML`, `CSV`, `UTC`) as identity passthroughs.
- **B. DeepL glossary API.** DeepL supports uploaded glossaries per
  language pair. More "correct" than post-processing but adds API
  surface and only covers exact source→target term pairs.
- **C. Pass DeepL the `context` parameter.** DeepL's v2 API has a
  `context` field (untranslated, used only to disambiguate). The
  `.po` reference comments (`#: admin-templates/sent-log-list.php`)
  or the `msgctxt` could feed it. Helps the polysemy class
  (`Sent`, `Folder`) without hand-maintaining every term.
- **D. Don't machine-translate `en_*` locales.** For en-GB/en-AU the
  right output is almost always the source string. A passthrough (or
  identity glossary) for `en_*` avoids inventing errors like
  `TLS` → "The latest security standards".
- **E. Acronym/short-string guard.** Skip DeepL for tokens that are
  all-caps ≤5 chars, or single words on a short denylist, and emit
  them verbatim for review.

## Done in the plugin (for the record)

All 8 `.po`/`.mo` locales in `heads-up-mailer/languages/` were
hand-corrected and recompiled on 2026-06-17 (en-GB plus the 7
above). These corrections live only in the plugin repo and are **not
reflected in this tool**, so a regen here will reintroduce the
errors until at least option A or D lands.
